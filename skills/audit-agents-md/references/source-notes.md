# 来源与适用范围

方法结合两类材料：作者对模型升级的建议，以及一次真实指令集合审计暴露的安装、触发和工作流衔接问题。技能主文保存可执行检查，案例文件保存条件化经验；本文件只说明来源。

## Eric Provencher 的文章

- 标题：Rethinking skills and prompts for GPT-6 Astra。
- 作者：Eric Provencher，`@pvncher`。
- [原帖](https://x.com/pvncher/status/2095991462416490862)，其中的[文章](https://x.com/i/article/2095989703967125509)。
- 发布于 2026-09-04；2026-09-05 读取。X 直接访问受限时，通过 [FxTwitter 同帖返回](https://api.fxtwitter.com/pvncher/status/2095991462416490862) 取得带文章 ID 和作者信息的正文。

本文的相关建议是：缩短并限定技能描述；按当前流程加载细节；减少对每次小修改都生效的全库阅读和验证流程；重审确认边界；开工前明确完成条件；考虑其他模型仍会使用同一套规则。这些是作者的指导观点，不是所有宿主或未来模型均成立的性能保证。

已读取材料足以审计时，复用这些有来源的原则。用户明确要求新的模型指南、最新实现或原文核验时，再读取对应一手材料；不能把无法访问的文章说成已经读过，也不能用相关帖子冒充指定帖子。

## writing-for-agents

用户指定的 `writing-for-agents` 提供了上下文指针、信息层级、完成标准、单一事实源和剪裁等方法。[上游项目](https://github.com/mattpocock/skills)。

存在本地版本时，以实际安装的 `SKILL.md` 和 `SKILL-MECHANICS.md` 为准，按需要读取。开始实质改写技能或 AGENTS.md 时应用该写作规范；审计技能保持基本检查自足，不要求每次为它加载整套写作资料。调用机制以实际宿主资料核验，不把某一种前言字段和工具名当作跨宿主协议。

## 本次经验的迁移边界

可迁移的是判断方法：检查别名与生成镜像、追踪工作区差异、区分已授权发布、核对真实引用、识别不能闭合的步骤。某次扫描得到的文件数量、安装路径、具体故障状态和模型成本不作为未来运行的默认事实。
