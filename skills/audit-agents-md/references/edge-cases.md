# 按主题查阅的边界案例

## 重复与生成来源

同名只是检查线索。先比较真实路径、内容摘要、宿主发现清单与生成规则：

- 多个路径解析到同一文件：记录别名，避免重复计算物理内容。
- 独立文件内容相同：确认是不是打包镜像，再判断是否重复发现。
- 同名内容不同：指出具体差异，按真实运行时/权威来源决定保留内容；文件更长不代表更新。
- 生成镜像：修改源和生成流程；个人安装若暴露两个入口，处理安装/分发范围。

扫描器记录磁盘事实，不能证明宿主究竟注入了多少描述、采用哪份入口，或是否发生了重复调用。

## 调用策略与宿主

按当前宿主的本地规范或官方资料核验策略。Codex 的 `agents/openai.yaml` 可用 `policy.allow_implicit_invocation: false` 表示只允许显式调用；单独出现 `disable-model-invocation: true` 时，核对宿主是否支持及是否需要对应设置。

用户原本选择手动调用时保留该选择；正常自动发现不是错误。审计任务不默认把所有技能改成手动。正文提到 `Skill`、`load_skill` 等工具时，核对当前是否真实可用；必要时改成宿主支持的读取方式或实际文件指针。

## 文件与技能引用

扫描出的不存在链接只是候选。代码围栏内的演示、`[文字](url)`、路径占位符、待生成产物、URL、锚点和 glob 不按现存文件要求处理。

真实引用从文档所在目录解析；跨技能引用核对当前已安装清单。缺少可选技能时，应有适用的降级路径；确实缺必要能力时准确说明，不能把目标技能的名字当作已执行。

扫描器只提取围栏外的常见内联 Markdown 链接。裸反引号路径、引用式链接和动态命令仍需按正文检查，文件存在也不代表链接锚点和语义正确。

## 完成与步骤衔接

| 已观察到的模式 | 检查方式 | 改写方向 |
|---|---|---|
| 声称审查未提交修改，但只比对 `base...HEAD` | 用隔离仓库比较提交差异与工作区差异 | 区分已提交、暂存、未暂存及未跟踪对象，固定本次覆盖集合 |
| 提交后验证，失败修复后直接推送 | 跟踪修复是否进入最终提交 | 把验证放在最终提交前，或明确重新提交任务内修复 |
| 原型完成后自动接入真实代码 | 对照用户只想观察还是已要求实施 | 原型结论与正式实施分支分别承接授权 |
| 没有可自动运行的复现就禁止诊断 | 检查日志、堆栈和调用链是否仍可区分原因 | 允许标明证据等级的取证，不把候选原因写成定论 |
| 任意测试都先确认接口 | 检查既有公开接口和用户验收是否已明确 | 只询问真实的接口/范围/环境分歧 |
| 普通审查触发技能后自动发 Issue | 区分模型选择技能与用户授权发布 | 普通审查交付结果；已有发布授权时继续完成，无需重复确认 |

这些是条件化检查，不是对同名技能永久有效的诊断。每次重新读取实际版本和相邻规则。

## 新模型与流程成本

强制四份预读、全部测试、多代理评估和多轮盲审都需要结合任务判断。图像格式、方向正确性、透明度、发布可见性和真实消费者验证，可能就是交付契约，不能按“新模型更强”删除。

区分三类结论：静态可确认的规则冲突；有理由尝试的简化；需要运行对照才能确认的 no-op/模型效果。行为评估用有区分力的实际任务，记录正确性、覆盖和成本；没有测量就只报告文字与结构变化。

重试出口以新增证据和收敛情况为依据。保留实际失败的修复要求，同时明确无新增信息时怎样报告剩余问题。主观评分、固定假设数量或“直到完美”不能单独定义完成。
